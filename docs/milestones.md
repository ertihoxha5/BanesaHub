## Scope and architecture boundaries

- MVP: FR-01–FR-10 and minimal FR-12 (private documents), including manual payments and a limited tenant portal. V1: FR-11 shared expense preview/allocation, advanced documents and notifications, richer reporting and vendor workflows. Bank integrations, mobile, predictive analytics and online payments are later options; no live payment provider without approval. Pricing and timing in the PDF are hypotheses.
- Separate MVC and Web API hosts in one modular monolith. Browser → MVC → versioned API → Application → Domain; Infrastructure implements persistence and other adapters. References: Application → Domain; Infrastructure → Application and Domain; API → Application and Infrastructure; Web calls API over HTTP and has no Infrastructure reference. Separate unit and integration test projects.
- MVC uses secure cookies and antiforgery; propose server-side API credentials/tokens for its API calls. Final session/token design belongs to M02. Identity, organization membership and resource checks enforce access; query filters supplement service checks. Platform administrators have limited metadata access.
- SQL Server and EF Core migrations; organization-scoped relationships, unique keys and concurrency controls. Contract overlap, monthly charge uniqueness, allocation limits and audited reversals require transactional verification. Use decimal money and ISO currency codes; UTC timestamps and local billing dates. Albanian UI, EUR and local formatting by default; English names in code and routes.
- Before M04–M06, confirm primary versus multiple tenants, first/last month and due-date policies, deposit handling and correction policy. The PDF proposes one primary tenant, no automatic MVP proration and deposits separate from income. Utility billing is V1; manual payments record what staff enter and do not verify a transfer.
- API baseline: /api/v1, OpenAPI, Problem Details, validated DTOs, pagination and sorting allowlists. HTTPS, structured logs with correlation IDs, private file storage, resource checks, accessible MVC states and SQL Server integration tests are acceptance work. Pilot performance target: main pages under 2 seconds under agreed conditions; review local privacy/retention obligations before using real data.
